# 每轮复核的具体任务

| 视角 | 核查任务 | 通用示例 |
|---|---|---|
| implementation | 代码操作、实际调用、开关、缺资产降级、参数来源、入口差异 | 附加元数据函数存在，但默认配置不启用 |
| consistency | 术语、符号/维度/单位、流程、实施例、输出边界 | 文字描述的加法操作是否与代码一致；输入输出格式是否一致 |
| adversarial | 找最强断言的反例与缺证据处，核查条件公平、混杂变量 | 数值变换源码不能支持未经测量的性能提升结论 |

每项问题定位到特征与代码/配置；提出可执行修改。收益问题优先收窄文字或补实验条件，不替发明人编造对照结果。新增技术方向放待确认队列。

修订后重读新正文及改动相关上下游，既查问题是否消失，也查修改是否引入术语/参数不一致。不得只是把blocking改成warning就算解决。

脚本防止缺出处、缺轮次、草稿或代码漂移、过期评审和未解决阻断项；无法判断公式数学真伪、语义支持、创造性、实验因果、真实身份或审阅记录诚实性。这些限制在交付状态中保留。
